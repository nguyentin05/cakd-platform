## SHARED STYLE GUIDE — CAKD Platform Docs

### Terminology (locked — never substitute these terms)
- `cakd` — the CLI binary name, always lowercase, always in backticks when referring to commands
- `platform.yaml` — always lowercase, always in backticks
- `bootstrap` — the act of running `cakd create` end-to-end
- `backing services` — PostgreSQL, Redis, RabbitMQ collectively
- `project` — the output directory generated by `cakd create`
- `template engine` — the component that renders Go templates into files
- `Terraform Bridge` — the component that creates GitHub repositories

### Tone & Voice
- Direct and concise — developer audience, no marketing language
- Active voice, second person: "Run the command" not "The user should run"
- Never use: "simply", "just", "easy", "straightforward", "powerful", "seamlessly"
- Code examples must be runnable — no placeholder logic that doesn't work

### Astro Starlight Conventions
- Use `:::tip`, `:::caution`, `:::danger` callouts for important notes
- All code blocks must have language specified: ```bash, ```yaml, ```go
- Internal links use relative paths: `[create](/reference/cli-create/)`
- Frontmatter is required on every page — never omit

### Output Rules
- Return ONLY valid Markdown — no explanation, no preamble
- Never wrap output in ```markdown code blocks
- Preserve all frontmatter exactly as-is unless a field value is factually wrong
- Do not add sections not listed in the template structure
